SEC-01 Shell Command Chaining & Operator Bypass in Auto Mode
Critical SOLVED IN CODE Security
Target File shell_tools.py (lines 52–71, 116–122)
Vulnerability Type Allowlist Evaluation Bypass via Shell Operators
Status SOLVED & VERIFIED
Test Verification SHELL-028, SHELL-029, SHELL-030, SHELL-031

Vulnerability Description

shell_tools.run_command extracts the program name by taking the first token from shlex.split(command)[0]. When compound shell commands were passed (using operators such as &&, ||, ;, |, &, or backticks/subshells $()), secondary binaries were able to execute in auto-mode without human approval.

Implemented Code Solution

Added _COMPOUND_OPERATORS = ("&&", "||", ";", "|", "&", "$(", "`") and _is_compound(command). Any compound command is intercepted before execution and redirected to confirm(f"Compound/chained command detected, approve anyway?\nrun: {command}", force_ask=True), forcing human confirmation regardless of auto-mode.

SEC-02 Subprocess Process Group Leak on Shell Timeout
High SOLVED IN CODE Robustness
Target File shell_tools.py (lines 127–156)
Defect Type Orphan Subprocess Resource Leak
Status SOLVED & VERIFIED
Test Verification SHELL-032, SHELL-033

Vulnerability Description

subprocess.run(command, shell=True, timeout=TIMEOUT_SECONDS) previously sent SIGKILL exclusively to the top-level shell process, leaving child background processes orphaned in the system.

Implemented Code Solution

Replaced with subprocess.Popen(..., start_new_session=True) to isolate child processes inside a dedicated process group. On timeout, os.killpg(os.getpgid(proc.pid), signal.SIGKILL) terminates the entire process group.

ROB-01 Signal / Thread Safety Conflict in Confirmation Gate
High SOLVED IN CODE Concurrency
Target File confirm.py (lines 55–92)
Defect Type POSIX Signal Handling from Worker Thread
Status SOLVED & VERIFIED
Test Verification CONFIRM-010–CONFIRM-012, CONFIRM-033

Vulnerability Description

Calling signal.signal(signal.SIGALRM) inside tools executed on worker threads inside ThreadPoolExecutor raises ValueError: signal only works in main thread.

Implemented Code Solution

Replaced signal.alarm with _read_input_with_timeout(), launching a background daemon thread that feeds a queue.Queue with result.get(timeout=timeout_seconds). Fully thread-safe and cross-platform.

ROB-02 Non-Atomic Persistence & Memory Corruption Wipe Hazard
High SOLVED IN CODE Data Integrity
Target File memory.py (lines 43–94)
Defect Type Unprotected Overwrite & Cascade File Loss
Status SOLVED & VERIFIED
Test Verification MEMORY-019, MEMORY-026, MEMORY-027

Vulnerability Description

Direct write to memory.json without atomic swap previously risked zeroing or corrupting the file if interrupted mid-write, resulting in total memory loss on next startup.

Implemented Code Solution

Implemented atomic file write via temporary file creation (.tmp{pid}) and os.replace(). In _load(), if JSON decoding fails, the corrupt file is backed up to .corrupt.bak rather than discarded.

ARCH-01 Static Module-Level Path & Config Binding
Medium DOCUMENTED TRADEOFF Architecture
Target File fs_tools.py (lines 37–48)
Defect Type Import-Time Global Path Resolution
Status DOCUMENTED & ACCEPTED
Design Scope Single-workspace CLI REPL process boundary

Architectural Analysis

BASE_DIR = Path.cwd().resolve() is resolved once at import time. This is a deliberate design simplicity choice for a single-workspace CLI. Multi-tenant servers should encapsulate paths in an injectable context object.

Design Documentation

Documented directly in fs_tools.py and architecture reports as an accepted tradeoff for the single-user CLI deployment model.

ROB-03 Alternating Tool Call Stuck-Loop Blindspot
Medium SOLVED IN CODE Agent Loop
Target File shared.py (lines 163–180, 353–366)
Defect Type ReAct Loop Stuck Detection Limitation
Status SOLVED & VERIFIED
Test Verification SHARED-050, SHARED-051, SHARED-052

Vulnerability Description

Stuck loop detection previously only checked single repeating tool calls, failing to detect alternating cycle patterns (A → B → A → B or A → B → C → A → B → C).

Implemented Code Solution

Integrated _detect_cycle(signatures, period, repeats) in shared.py to check 2-step and 3-step periodic sequence repetitions, stopping oscillating agents before exhausting iteration limits.

ROB-04 Unbounded History Growth & Summarization Context Bloat
Medium SOLVED IN CODE Robustness
Target File memory.py (lines 184–213)
Defect Type Unbounded Context Window Accumulation
Status SOLVED & VERIFIED
Test Verification MEMORY-028, MEMORY-029

Vulnerability Description

Context in long multi-turn sessions accumulates. End-of-session auto-summarization previously sent all historical conversation turns to Ollama, risking prompt overflow.

Implemented Code Solution

In memory.save_session_summary, the conversation is windowed: windowed_messages = messages[-MEMORY_SUMMARY_MAX_MESSAGES:] (default 40 messages), safeguarding the LLM context length at shutdown.
